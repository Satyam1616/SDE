## 19. Interview Preparation Framework

### 19.1 Online Assessment (OA) Preparation

| Aspect | Strategy |
|--------|----------|
| **DSA** | Focus on Medium LeetCode (80% of OA questions). Time: 30-40 min per problem. |
| **Speed** | Practice timed: solve 2 medium in 60 min |
| **MCQs** | CS fundamentals MCQs from IndiaBix/GFG quiz (OS, DBMS, Networks, OOP) |
| **Debugging** | Practice reading broken code and fixing it (HackerRank style) |
| **Output prediction** | JS/C++ output questions — scope, hoisting, closures, prototypes |

**OA Practice Plan:**
- Week 20-22: 3 timed tests per week (LeetCode contest or custom)
- Each test: 2-3 problems, 75 minutes, no IDE help

---

### 19.2 Technical Interview Preparation

#### Round 1: Coding (DSA)

**Format:** 1-2 problems in 45-60 minutes. Explain while you code.

**Strategy:**
1. Think out loud — interviewer wants to hear your process
2. Start with brute force, state complexity, then optimize
3. Ask clarifying questions before coding
4. Write clean code with meaningful variable names
5. Test with examples + edge cases
6. State time and space complexity

**Common Mistakes:**
- Starting to code before thinking
- Not asking clarifying questions
- Silent coding
- Not testing edge cases
- Ignoring complexity analysis

#### Round 2: System Design / Technical Deep Dive

**For SDE-1:** Usually a simpler design or deep dive into your project.

**Prepare:**
- 4 system designs thoroughly (URL shortener, chat, feed, notification)
- Every architectural decision in your projects
- Database schema design reasoning

#### Round 3: CS Fundamentals / Language Specific

**Prepare the top 15 questions from each:**
- OOP (Section 6.1)
- DBMS (Section 6.2)
- OS (Section 6.3)
- Networks (Section 6.4)
- JavaScript (Section 7)
- React (Section 8)
- Node.js/Express (Section 9)

### 19.3 HR/Behavioral Interview

#### Must-Prepare Questions

| Question | Framework |
|----------|-----------|
| **Tell me about yourself** | 2-minute pitch: Education → Skills → Experience → Goal |
| **Why should we hire you?** | 3 strengths matched to job description |
| **Why this company?** | Research: product, culture, tech stack, recent news |
| **Strength** | Technical strength + example |
| **Weakness** | Real weakness + how you're improving |
| **Tell me about a challenge** | STAR: Situation → Task → Action → Result |
| **Tell me about a failure** | What happened → What you learned → How you improved |
| **Teamwork example** | Collaboration + communication + conflict resolution |
| **Where do you see yourself in 5 years?** | Growth in engineering, leadership aspirations |
| **Why did you choose CS?** | Genuine passion story |

#### STAR Method (Use for ALL behavioral questions)

```
S — Situation: Set the context (project, internship, hackathon)
T — Task: What was your responsibility?
A — Action: What specific steps did YOU take?
R — Result: What was the outcome? (Quantify if possible)
```

**Prepare 5 STAR stories** covering: teamwork, leadership, failure, conflict, technical challenge. These 5 stories can answer 90% of behavioral questions.

## 20. Project Interview Framework

### Deep Preparation Template (Do This for EACH Project)

#### Layer 1: Overview (30-second elevator pitch)

> "I built [ProjectName], a [what it does] using [tech stack]. It handles [key feature] and I designed it with [architectural highlight]. The most challenging part was [challenge], which I solved by [solution]."

#### Layer 2: Architecture Deep Dive

Prepare a mental diagram you can draw:
```
Client (React) → API Gateway (Express) → Services → Database (MongoDB)
                                      → Cache (Redis)
                                      → WebSocket (Socket.io)
```

Be ready to explain:
- Why each technology was chosen
- How data flows through the system
- Request/response lifecycle for a specific feature

#### Layer 3: Technical Decisions

| Decision | Prepare Answer For |
|----------|-------------------|
| Why React? | Component model, ecosystem, hiring demand |
| Why MongoDB over SQL? | Schema flexibility, document model fits your data |
| Why JWT over sessions? | Stateless, scalable, but explain trade-offs |
| Why Redux? | Complex state, predictable, devtools |
| Why Express? | Lightweight, flexible, Node.js ecosystem |
| Why Socket.io? | WebSocket abstraction, fallback support, rooms |

#### Layer 4: Scaling Questions

| Question | Approach |
|----------|---------|
| What if 100K users? | Horizontal scaling, load balancer, DB replicas |
| What if DB is slow? | Indexing, caching (Redis), query optimization |
| What if a server crashes? | Health checks, auto-restart, redundancy |
| How to handle concurrent writes? | Optimistic locking, queuing |
| What about data consistency? | Transaction support, eventual consistency trade-off |

#### Layer 5: What I'd Improve

Always have 2-3 genuine improvements:
- "I'd add comprehensive testing — I have basic tests but want 80%+ coverage"
- "I'd implement a CI/CD pipeline for automated deployment"
- "I'd add monitoring and alerting using something like Datadog"
- "I'd refactor the auth to support OAuth for social login"

## 21. Job Application Strategy

### When to Start Applying

> **Start at Month 4 (6-month plan) or Week 10 (3-month plan).** You don't need to be 100% ready. Interviewing IS preparation.

**Readiness threshold to start:**
- ✅ 150+ DSA problems solved
- ✅ Can explain OOP, DBMS, OS basics
- ✅ 1 project deployed with auth
- ✅ Resume ready

### Application Channels

| Channel | Strategy | Priority |
|---------|----------|----------|
| **LinkedIn** | Optimize profile, connect with recruiters, apply via Easy Apply | HIGH |
| **Company Career Pages** | Apply directly to target companies | HIGH |
| **Referrals** | Ask connections, alumni, LinkedIn network | HIGHEST |
| **Naukri** | Updated profile, apply to relevant postings | HIGH |
| **Instahyre** | Good for startup roles | MEDIUM |
| **Wellfound (AngelList)** | Startup-focused roles | MEDIUM |
| **Cold Outreach** | Message hiring managers/engineers on LinkedIn | MEDIUM |
| **Campus Placement** | If available, prepare specifically for visiting companies | HIGH |

### Application Volume

| Week | Applications | Focus |
|------|-------------|-------|
| Starting week | 10-15 | Test the process, get feedback |
| Ongoing | 15-25/week | Diversify: mix of dream, target, safety companies |
| Active interview phase | 10/week + interviews | Reduce applications, focus on interviews |

### Company Categories

| Category | Description | Application Mix |
|----------|-------------|----------------|
| **Dream** | FAANG, top startups | 20% of applications |
| **Target** | Good companies, realistic match | 50% of applications |
| **Safety** | Smaller companies, service-based | 30% of applications |

### Resume Tips (Quick)

1. **One page only**
2. **Education, Skills, Experience, Projects** — in that order
3. **Quantify results:** "Reduced API response time by 40%" not "Improved performance"
4. **Match keywords** from job description
5. **Projects section:** Name + tech stack + 3 bullet points with impact
6. **No objective statement** — use a skills summary if needed
7. **Clean formatting** — use a proven template (Jake's Resume, Deedy)
